# Click-to-Safe Mobile

A native React Native / Expo app using the **Hackathon Submission** variant from the [Road Receipts handover](https://github.com/whyteaz/road-receipts-handover/tree/9b9f293/variants/hackathon-submission). It uses the supplied Manrope typography, white surfaces, Gemini Blue, pill actions, and native motion. See [the implementation notes](design/SUBMISSION_SYNC.md) for provenance and integration boundaries.

This repository contains the mobile client. It connects to the existing [GCP review backend](https://github.com/Lorem-Ipsum-AI-Builder-Cup-2026/prototype); no backend deployment is needed for this UI rebuild.

## Run locally

Requires Node.js 22 and npm. iOS requires macOS/Xcode/CocoaPods; Android requires JDK 17, Android Studio and SDK 36.

```sh
git clone https://github.com/Lorem-Ipsum-AI-Builder-Cup-2026/drivereport-mobile.git
cd drivereport-mobile
npm ci
npm run ios                 # native development build and Simulator
# npm run android           # native Android development build
```

The display name and launcher icons are **Click-to-Safe**. The repository URL and storage keys remain stable. The TestFlight app uses the team-owned iOS bundle identifier `app.aibuildercup.clicktosafe2`; older USB development installs used `com.example.safetycar.dev`. They are separate iOS apps and do not automatically share saved footage or Keychain settings.

After installing the native development app:

```sh
npx expo start --dev-client --lan
```

Rebuild after changing native dependencies, config plugins or `app.json`. Native `ios/` and `android/` directories are generated by Expo and excluded from Git. Regenerate an existing native project with `npx expo prebuild --platform ios` when moving from the old development identifier to the TestFlight identifier.

For a physical iPhone, connect/trust it, enable Developer Mode, sign into Xcode, configure your development team, and run `npx expo run:ios --device`. Keep the phone and Metro computer on the same Wi-Fi network and allow local-network access.

## EAS and TestFlight

The app is linked to [YUYU Corp / Click-to-Safe](https://expo.dev/accounts/yuyu-corp/projects/click-to-safe), project ID `bf9e5ab8-8b00-405e-8f56-87fed2ec2910`.

```sh
npx eas-cli@latest login
npx eas-cli@latest build --platform ios --profile production
npx eas-cli@latest submit --platform ios --profile production
```

The `production` profile creates a standalone Release build for App Store Connect / TestFlight. Signing credentials and the submission API key are managed by EAS for the existing Apple team. Do not commit provisioning profiles, certificates, private keys, API tokens, or `credentials.json`.

The `preview` profile is a separate ad hoc distribution option and requires its own provisioning profile containing each tester's device UDID. The supplied App Store profile cannot be used for direct installation from an Expo build URL. External TestFlight installation links require an App Store Connect app record, a processed build, beta test metadata, and Apple's Beta App Review approval. A build dashboard URL is not a TestFlight invitation.

The judging build explicitly embeds the existing test API token from the production EAS variable `EXPO_PUBLIC_JUDGING_API_TOKEN`. Fresh installs and updates use that token and the fixed API URL without manual setup. The value is never committed to Git, but it is extractable from the distributed binary. This is a limited judging distribution, not a production authentication design. Backend code and credentials are unchanged. Builds without this variable retain manual connection settings.

## App flow

- **Home:** “Spotted an asshole? Let’s take their licence.” with rolling JAPAC road statistics and staggered entrances, an Analyse a clip action, and a secondary recording action. The clip tray preloads a real 43-second dashcam sample (`assets/sample-video.mp4`) and accepts a file or saved recording. Whichever clip is selected, Analyse with Gemini uploads it and runs the real review; the synthetic demo is only reachable from Developer. The black recording screen retains its elapsed clock and End recording action.
- **Analysis:** footage, four stage indicators (Upload, Watch, Law, Judge), rotating Gemini spark, scan sweep, caption transitions, arriving findings, stamped points and a sample cost counter. Demo stages are simulated and labelled. Live mode shows actual upload progress, then waits for the server's single review response without inventing agent progress.
- **Cases:** live mode loads `GET /v1/reviews` on startup and foreground entry, downloads new review details, and deduplicates them by `review_id`. Devices using the same judging credential therefore see the same backend case history. Local edits and retained device footage survive a refresh; server reporting state and expiring evidence links remain refreshable. The page supports an explicit retry when history is unavailable. Demo cases stay local and separate.
- **WhatsApp:** live Malaysia cases open a prefilled draft to JPJ's published traffic-offence WhatsApp hotline, `+60 13-449 8997`; Settings → Official JPJ WhatsApp can change the number if it ever needs to (the Settings row then reads "Authority WhatsApp" and offers "Use JPJ hotline again"). Submission samples use a recipientless chat picker, and the separate Test WhatsApp utility uses only the tester's configured number. Before opening a live draft, the app refreshes expiring evidence links and includes the cited excerpt link when the server produced one; the original clip remains available for manual attachment. Opening WhatsApp records an `opened` state, but does not mark a report sent. The user confirms sending, sees a printing receipt and Reported stamp, then taps See your impact to start the eight-second Undo window. A lasting “Mark as not sent” action remains available.
- **Impact:** filter by date, offence, plate and reporting status. Live mode reads the server's period totals and most-spotted plate while the case list remains the device's retained evidence. Reporting `opened`/`sent` changes are synchronized to the server for new reviews. Demo mode keeps its synthetic counters and licence meter. Live authority outcomes and licence records remain unknown because the server does not provide them.
- **Developer:** available from Settings, with test recipient, API connection, retained-clip retry and synthetic demo controls. The main navigation is Home / Cases / Impact.
- **Settings:** jurisdiction-specific recipients, optional reporter details, locale and reduced motion. Profile details are opt-in for WhatsApp and are never sent to the analysis API.

The initial screen is always Home. Previous DriveReport evidence remains in local storage and completed reviews migrate into the new case model. Demo cases and real records remain separate. Simulator defaults to demo; a physical device defaults to live recording. Demo recording captures no camera footage, and demo findings are not real incidents.

JPJ's [official social-channel announcement](https://t.me/s/JPJ_Malaysia?before=208) lists `013-449 8997` for public reports about emergency-lane misuse, queue cutting and other traffic offences. [Current JPJ guidance](https://www.jpj.gov.my/e-aduanjpj/) also lists MyJPJ e-Aduan and `aduantrafik@jpj.gov.my`. The WhatsApp draft is user-controlled: the app never taps Send and does not claim JPJ acceptance or enforcement. The reporter should provide full name, identity number, postal address and phone number when JPJ requires witness details.

## Recording and storage

A drive is one silent 720p video, up to **30 minutes**. Capture never restarts at a one-minute boundary. End recording, the 30-minute limit, or the 490 MiB capture ceiling finishes that one file, then starts upload and review. The 2 Mbps video bitrate targets roughly 450 MB for 30 minutes; device encoders and available storage can cause an earlier stop.

The app keeps the screen awake and needs at least 1,100 MiB free before capture, allowing room for the camera file and durable local copy. Leaving the foreground or locking the phone stops capture. Saved videos remain available in Developer; older recordings are not deleted automatically.

End recording keeps the camera mounted while showing local saving progress. After the native callback, the original is copied and indexed before optional thumbnails. Native capture stops at 29:59 to leave one second of container timing headroom under the server’s exact 30-minute limit. The analysis screen then shows video preparation, upload progress, and server review. A drive produces one upload, not 30 uploads. For longer videos the review request chooses a larger analysis window, keeping the server request inside its time budget without splitting the stored video. Without credentials it stays saved locally. This is post-drive review, not real-time violation detection.

Gallery/file imports accept videos up to **30 minutes and 500 MiB**. Before any new upload, the app inspects the file. If it has audio, the local `VideoPreparation` Expo module copies only encoded video tracks to a temporary MOV (iOS) or MP4 (Android), preserving quality and orientation. It verifies the output contains no audio and retains the video's duration before requesting an upload URL. A failed conversion never falls back to uploading audio. Originals stay intact locally, and temporary silent copies are deleted after upload or failure. Legacy uploads without an audio-free marker are not reused for a new analysis.

The native module requires a new app binary (it cannot be installed through a JS-only update or Expo Go). `npm test` covers duration/size boundaries, single-file capture and upload behavior. `tests/SilentVideoExporterCheck.swift` runs the same AVFoundation exporter against a supplied audio/video fixture and checks duration, track removal, cancellation, and preservation of the original.

## Backend connection

For builds without the judging environment variable, enter an HTTPS base URL and Bearer access token in **Developer → Backend settings**, then save. Manual credentials use device SecureStore. The judging build described above instead embeds its preconfigured test token and hides connection editing. Neither credential value is committed to Git.

The existing development base URL is `https://prototype-video-api-fydsujlsyq-uc.a.run.app`. “Check URL” calls `/health`; it does not validate the token.

The mobile client follows the current backend contract:

1. `POST /v1/uploads` with `mime_type` and `size_bytes`.
2. Binary `PUT` to the returned upload URL.
3. `POST /v1/review` with `video_uri`, `mime_type` and the selected `region`.
4. Preserve the returned `review_id`, `case`, `decision_trail`, tracks and signed original/annotated/excerpt video links. Older stored responses continue through the legacy mapper.
5. `GET /v1/reviews` pages through shared history; unseen `review_id` values are loaded into the device's Cases list.
6. `GET /v1/reviews/{review_id}` downloads a new shared case and refreshes expiring signed evidence links before handoff.
7. `PATCH /v1/reviews/{review_id}/reporting` synchronizes `opened` and `sent`; `GET /v1/impact?period=all|week|today` supplies live aggregate counters.

The backend accepts one video up to 30 minutes and 500 MiB. It now persists a normalized case, decision trail, tracked/annotated evidence and a cited excerpt when rendering succeeds. Signed links expire, so the app refreshes them before WhatsApp handoff. The backend still has no progress-event stream, face blurring, direct authority submission, verified fine outcomes or licence records. Those capabilities are not fabricated in live mode. Keep the app open while reviewing; stopping local waiting cannot cancel an already-started server job.

Optional provisioning for contributors with existing GCP Secret Manager access:

```sh
npm run provision:ios
npm run provision:android
npm run provision:iphone -- <iphone-udid>
```

These scripts require authenticated `gcloud` access to `prototype-public-api-token` in project `aitech-good-s27493`; Android also needs `adb`, and iPhone provisioning needs `afcclient`. They transfer a temporary file into the development app's sandbox, which imports credentials into SecureStore and deletes the file. Release builds do not import it. Tokens are not printed. Public distribution requires user-scoped authentication and request limits in place of the shared development token.

## Repeat the live AI smoke test

Tap **Analyse a clip**, keep the preloaded sample and tap **Analyse with Gemini**. This copies the bundled real MP4 into the evidence store and calls the configured upload/review endpoints; it does not use the synthetic demo fixtures. A valid API token and Malaysia region are required. Gemini usage is billed to the configured backend. Analysing the sample again reuses its waiting case; once that case is marked sent, the next run starts a fresh upload and review. In a development build, **Developer → Load sample video** then **Analyse video** always imports a fresh copy for a repeatable run.

Wait for the final result, open Review, and check that the original footage and returned findings/citations are present. Missing plate/date/location remain editable rather than being invented. Loading the sample alone does not upload it or start analysis.

## Motion implementation

Most UI is native React Native. Tab icons interpolate the new supplied 72-point SVG geometry over 540 ms, accompanied by a stretching active pill. Deeper routes slide over the previous screen; tabs fade. Home digits roll and country names wipe every 3.4 seconds; receipts reveal over 900 ms, points/Reported stamps land over 460 ms, and the licence meter fills over 900 ms. Case switches and analysis rows use native-driver transitions. Reduced motion respects both the app preference and the system setting.

Only the 230-point Living intelligence illustration uses a local WebView, to retain the authored Canvas renderer exactly: a bounded 72-particle field, at most 96 connections, a steady Gemini mark, and a settling receipt/check composition. Fonts, image, CSS and JavaScript are embedded locally; the view blocks external navigation and has a restrictive content security policy. Motion pauses outside the measured scroll viewport, in the background and in reduced-motion mode, and the illustration is destroyed when leaving the screen.

After changing its source assets, regenerate the embedded module:

```sh
npm run build:motion
```
