# DriveReport Mobile

A React Native app for reviewing dashcam footage and preparing evidence-based road incident reports. Built with Expo SDK 54, React Native 0.81, TypeScript, and Expo Router, with a dark interface for iOS and Android.

The mobile client connects to the organization's [GCP video review backend](https://github.com/Lorem-Ipsum-AI-Builder-Cup-2026/prototype). This repository contains the mobile application only and can be cloned independently.

## Features

- Import videos from Photos or Files, record a short camera clip, or try the bundled 12-second sample.
- Upload footage directly to Cloud Storage and request a multi-agent video and legal review.
- Inspect the original video, timestamped observations, vehicle-specific findings, AI confidence, and cited legal references.
- Select a vehicle and manually verify its plate, incident location, and incident date/time.
- Prepare and edit a WhatsApp report draft, copy the message, and share the original video separately.
- Save evidence and drafts locally, filter filing history, and recover interrupted reviews.
- Store connection credentials and optional reporter details in device secure storage.

Real-time bounding boxes are intentionally out of scope. Reports are never sent automatically. Authority delivery receipts and case decisions are not tracked.

## Requirements

- Node.js 22 (`.nvmrc`) and npm.
- iOS: macOS, Xcode, CocoaPods, and either an iOS Simulator or a connected iPhone.
- Android: JDK 17, Android Studio, Android SDK 36, and an emulator or connected device.
- A backend API URL and access token to run cloud analysis.

See [VALIDATION.md](./VALIDATION.md) for the environments and flows that have been tested.

## Quick start

```sh
git clone https://github.com/Lorem-Ipsum-AI-Builder-Cup-2026/drivereport-mobile.git
cd drivereport-mobile
npm ci

# Build and launch a native development app.
npm run ios
# Or:
npm run android
```

After the first native build, start Metro for JavaScript and TypeScript development:

```sh
npm start
```

Rebuild after changing native dependencies, config plugins, or `app.json`. The `ios/` and `android/` directories are generated by Expo and excluded from Git; do not edit them manually.

## Connect the backend

Open **Settings → Cloud analysis** in the app, enter the server URL and Bearer token, and save.

The configured development server is:

```text
https://prototype-video-api-fydsujlsyq-uc.a.run.app
```

The connection check calls the public `/health` endpoint. The access token is verified when an upload is requested. Tokens are stored in SecureStore and are not included in source control or the JavaScript bundle.

### API flow

1. `POST /v1/uploads` with `mime_type` and `size_bytes`.
2. Binary `PUT` to the returned Cloud Storage upload URL.
3. `POST /v1/review` with the returned `video_uri` and `mime_type`.
4. Validate and save the returned verdict, findings, and evidence timeline.

The client accepts MP4, MOV, WebM, and MPEG clips up to 500 MiB. The backend limits duration to 10 minutes. In-app recording is silent 720p video, limited to 60 seconds.

### Optional development provisioning

Contributors who already have access to the existing GCP Secret Manager secret can provision a local development installation without copying a token into chat or source files:

```sh
# Run after installing the app.
npm run provision:ios       # Booted iOS Simulator
npm run provision:android   # One connected Android development device
npm run provision:iphone -- <iphone-udid>
```

These scripts require an authenticated `gcloud` CLI with access to secret `prototype-public-api-token` in project `aitech-good-s27493`. Android also requires `adb`; physical iPhone provisioning requires `afcclient` from libimobiledevice (`brew install ideviceinstaller`).

The scripts transfer a temporary connection file only into the app's own sandbox. On its next launch or reload, the development app moves the credentials into SecureStore and deletes the file. Release builds do not import these files. No token is printed by the scripts.

The existing backend uses a shared development token. User-scoped authentication, authorization, and request limits are required before public distribution.

## Run on a physical iPhone

1. Connect the iPhone to the Mac, trust the computer, and enable Developer Mode.
2. Sign in to an Apple account in **Xcode → Settings → Accounts**.
3. Configure the development team and run:

   ```sh
   npx expo run:ios --device
   ```

4. Keep the Mac and iPhone on the same Wi-Fi network and start Metro:

   ```sh
   npx expo start --dev-client --lan
   ```

5. Open the installed development app and configure its backend connection.

The app does not require Push Notifications. The config plugin removes that unused entitlement so a Personal Team can sign the development app. The current bundle identifier is `com.example.safetycar.dev`; use a team-owned identifier before distribution. Xcode must support the connected device for automatic deployment and debugging.

## Storage and report behavior

- Videos, thumbnails, review results, and drafts are stored on the device.
- Profile details are not sent to the AI API. If provided, they are included in the editable report draft.
- Upload progress reflects actual transferred bytes. The server returns the AI review as one response, so individual agent completion percentages are not displayed.
- Keep the app in the foreground during review. Long clips may take several minutes or longer.
- Interrupted sessions can be retried. Completed uploads are reused when retrying against the same server.
- Stopping a request ends local waiting or upload; an already-running server review may still finish.
- Deleting local evidence does not delete Cloud Storage copies. The backend currently exposes no deletion endpoint.
- WhatsApp receives the draft text only. Attach the original video separately using the share action.
- Set a verified recipient's international phone number in Settings. Opening a draft does not mean it was sent or received.
- The **Reported** status is a manual local confirmation by the user.
